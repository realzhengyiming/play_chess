# Codex 目标：让空间棋排布又好、又紧凑、又快

## 总目标

把当前“按单件家具落子”的系统升级为分层空间棋：先选择完整功能模块，再摆模块内对象，最后用地面、墙面和对象关系做全局验收。不能靠少摆家具、活动区假家具或后处理加分过关。当前只优化并开放“丰富”模式；“疏朗 / 标准”灰化，不参与验收和性能目标。

## 阶段一：最佳效果

- 优先完成床组、工作组、会客组、餐组、收纳组，而不是累计孤立小件数量。
- 对象评价、地面评价、墙面评价共同决定总分；任何严重缺陷不能被别项高分抵消。
- 地面扣分：不可达口袋、狭窄死角、家具把空间切断、重心严重偏斜、大片无意义留白。
- 墙面扣分：8–42cm 无用缝、42–68cm 尴尬缝、角落未收口、柜体断断续续。
- 大房间必须挑战完整客餐厅等面积档模块，不能用落地灯、小边几凑件数。
- 后处理新增实体必须重新验收地面和墙面；不合格就撤销。活动区只作留白说明，不生成免碰撞家具。
- 固定质量基准 12/12 通过，且无严重墙缝；大客厅模块分不低于 85。
- 浏览器截图人工复核后提交：`feat(layout): prioritize designer-quality compact layouts`。

## 阶段二：最佳速度

- 以阶段一提交作为不可退化基线，记录固定样例的分数、模块、死角、墙缝和耗时。
- 先分析候选生成、地面复核、Beam 宽度和重复最终评分；优化缓存、增量指标和分层搜索。
- 固定样例质量必须全部保持通过，关键字段不得下降到门槛以下。
- 目标：质量版 p95 约 2.9 秒降到 1.45 秒以内，或至少提速 2 倍。
- 浏览器复核后提交：`perf(layout): accelerate quality-preserving layout search`。
- 浏览器主引擎保留 JavaScript。只有基准证明 Python 关键内核连同通信成本仍明显更快，才引入 Python；不能凭感觉迁移。
