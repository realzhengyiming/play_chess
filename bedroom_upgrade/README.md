# 卧室空间棋升级分支

此目录是与根目录旧版完全分开的卧室模块棋实验分支。

## 入口

- 新版页面：`bedroom-space-chess-V3_upgrade.html`
- 思路报告：`docs/空间棋卧室升级版思路精髓-V2.md`
- 棋谱数据：`data/bedroom-patterns.js`
- 房间拓扑内核：`assets/bedroom-room-topology.js`
- 模块搜索内核：`assets/bedroom-module-engine.js`
- 页面交互：`assets/bedroom-upgrade-ui.js`
- 自动测试：`tests/bedroom-module-engine.test.js`

页面还可以读取根目录旧版 `samples/*.json` 户型识别结果：

- 通过静态服务打开时，可直接选择内置样例；
- 直接双击 HTML 时，可使用“选择本地 JSON”；
- 载入后选择识别出的卧室；
- 正交矩形、L 形、缺角和带凹位卧室会按真实多边形进入搜索；
- 识别出的门窗会绑定到真实墙段；
- 斜墙当前会明确标记为暂不支持，不会用外接矩形冒充结果。

## 启动

推荐在项目根目录启动统一服务：

```powershell
uv run --frozen room-chess-server
```

然后访问：

```text
http://127.0.0.1:8765/bedroom_upgrade/bedroom-space-chess-V3_upgrade.html
```

## 测试

```powershell
node bedroom_upgrade/tests/bedroom-module-engine.test.js
node bedroom_upgrade/tests/bedroom-golden-regression.test.js
```

金牌回归命令会读取 `goldens/bedroom-golden-cases.json`，批量验证棋谱、必要模块、床头柜数量、凹角柜朝向、封墙、漏摆机会、全局分和性能上限，并生成 `artifacts/golden-regression-latest.json`。

启动服务后可打开：

```text
http://127.0.0.1:8765/bedroom_upgrade/bedroom-golden-regression.html
```

## 拓扑与方案保存

- 每次下棋后自动把当前真实多边形、墙段、门窗、棋谱和首选方案写入浏览器 `localStorage`；
- 刷新页面会重新编译并恢复上次保存的拓扑；
- 点击“导出拓扑与方案 JSON”可获得可复现的完整快照。

## 当前诊断能力

- 逐模块统计原始候选、硬合法候选、进入 Beam 的候选与主要淘汰原因；
- 计算可用墙长、剩余墙段、最大未利用墙段和空间利用评分；
- 棋谱可定义“一对多”软关系：媒体组可在睡眠组与休闲组之间选择满足度最高的观看目标；
- 正对、偏移、朝向、距离与视线均为渐进评分，轻微偏移不会被硬性淘汰；
- 关系支持正向偏好、负向回避和有优先级的替代目标：床是卧室媒体的主目标，休闲座位为降级目标，工作组则回避媒体观看轴；
- 床与门口的隐私关系已配置化：床尾越直指门口、轴线越重合、距离越近且视线越通透，隐私分越低；它是软规范，不是硬禁止；
- 单人床具有单床头柜与双床头柜两种变例，主棋后会在不重排床的前提下尝试补全第二个床头柜；
- 高柜与定制柜会计算柜前使用区对相邻空墙的封堵长度，局部分与全局分同时扣除这项墙面机会成本；
- L 形凹角的柜类模块不得为贪用短横墙而把柜门朝向相邻长墙；高柜和薄柜统一优先依附长竖墙、朝开阔区开启；
- Beam 保留不同功能—墙段—位置组合的代表棋局，避免高分同质局面挤掉能继续摆入家具的分支；
- 根据房间面积提高预期模块容量，避免超大房间只放固定五个模块却仍获得虚高分；
- 8×8m 低利用率卧室会明确判为未通过，而不是继续得到 95 分以上。
- 页面展示总运行时间（ms）和压缩 Beam 棋谱树；树的每一层展示候选数、保留数、截断分支、本方案选择与该层耗时（µs）。
- 终局机会裁判会在剩余墙段上反事实尝试尚未落下的正式模块；若仍可通过越界、碰撞、门窗、使用区和凹角朝向等所有硬规则，则记为漏摆机会并扣除终局分。
- 自动模式会让局型适配度接近的最多两条棋谱分别完成 Beam 搜索，再用“全局质量分 + 局型适配小加分”进入组合决赛；总竞赛受 240ms 预算约束，页面可查看每个方案的来源棋谱与单谱耗时。
- 棋盘统一绘制语义正面箭头：床显示床尾方向，柜体显示柜门方向，媒体、座椅和梳妆位显示实际正面；书桌单独区分“朝房间的家具使用面”和“人朝墙看桌面的坐姿视线”。家具方向与关系检查可分别开关。
- 已落模块可逐个锁定，再执行“锁定后局部重排”；搜索以锁定模块作为既有棋局，只重新生成其余模块，适合保留床或柜体后快速修正局部。
- 页面启动时读取旧版 `/api/furniture-config`，把 `furnitureLibrary` 中的卧室家具及其 variants 编译成模块棋尺寸能力包；棋谱仍负责功能顺序和关系语义，家具配置只负责实际模数。接口不可用时自动回退到内置稳定模数。

## 当前边界

- 支持矩形和正交异形卧室，暂不支持斜墙；
- 识别房间使用真实门窗；手工宽深预设仍使用默认门窗；
- 使用三条棋谱：标准外围型、狭长酒店型、大卧室套间型；
- Beam 固定为 16；
- 模块只在墙端、墙中、门窗边界等语义临界点落子；
- 当前通行检查已经使用真实多边形栅格，但仍是升级分支的首轮验收；下一阶段继续接入旧主引擎的 0.50m 与零孤岛精确验收；
- 已接入可重复的“定制柜收纳组”残局模块：主棋结束后读取剩余墙段，动态生成 0.1m 级宽度的高柜或薄柜；
- 定制柜只按 0.35 个功能容量单位计分，能够改善收纳与墙面利用，但不能替代工作区、休闲区等正式功能分区；
- 当前狭长酒店棋谱已接入媒体组→睡眠组/休闲组的可替代软正对关系；后续由金牌样例校准容差和权重；
- 超大卧室的下一阶段重点仍是先划分功能子区，再在各子区落正式模块。

根目录下的 `bedroom-space-chess-V3.html`、`assets/js/space-chess.js` 和现有配置均未被本分支修改。
